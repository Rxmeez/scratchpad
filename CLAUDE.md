# CLAUDE.md — Scratchpad Repo Conventions

This file documents the conventions for `zero_rxpc` (or any agent) publishing
artifacts to this repo. Read this before adding a new artifact.

## Slug Convention

Every artifact slug **must be prefixed with the publish date** in `YYYY-MM-DD`
format, followed by a hyphen and a short kebab-case title slug:

```
artifacts/<YYYY-MM-DD>-<short-title-slug>/index.html
```

Examples:
- `artifacts/2026-08-18-rate-limiting/index.html`
- `artifacts/2026-08-17-log-based-cdc/index.html`

**Why:** without a date prefix, topic slugs eventually collide (e.g. two
different "caching" write-ups both wanting the slug `caching`). The date
prefix guarantees uniqueness and also makes the artifacts directory
naturally sortable/scannable by publish date.

The `slug` field in `artifacts.json` must match the directory name exactly
(date prefix included).

## Quiz Rules

If an artifact includes an interactive quiz at the bottom:
- **Minimum 3 questions, maximum 5 questions.**
- Each question needs 4 options, one correct, with a substantive
  explanation for every option (why it's right or wrong) — not just the
  correct one.
- Follow the existing quiz markup/JS pattern already used across artifacts
  (`.quiz-opt` buttons with `data-correct`, `#quiz-explain` reveal box,
  shared `answer()` script). Don't reinvent it per artifact.
- Quizzes are optional — only add one if it genuinely helps cement the
  material (technical/conceptual topics benefit; buying guides / meta pages
  don't need one).

## Further Reading

Every knowledge/explainer artifact (not meta pages like the welcome page)
should end with a **"Further Reading"** section right before the footer,
linking to a handful (3-5) of real, relevant external resources — official
docs, well-regarded blog posts, RFCs, etc. Use real URLs only, never
fabricated links.

## General Structure

```
/
  index.html            ← homepage, auto-generated by build.py — do not hand-edit
  index_template.html   ← homepage template (has <!--ARTIFACT_CARDS--> marker)
  artifacts.json         ← metadata for every artifact (title, date, topic, slug)
  build.py               ← regenerates index.html from artifacts.json + template
  assets/style.css       ← shared site styling
  artifacts/
    <YYYY-MM-DD>-<slug>/index.html  ← one folder per artifact
```

## Publishing Checklist

1. Pick a slug: `<YYYY-MM-DD>-<short-title>`.
2. Write the artifact as a self-contained `artifacts/<slug>/index.html`
   (link back to `../../assets/style.css` and `../../` for the homepage).
3. If it's a knowledge artifact, add a "Further Reading" section near the
   bottom with 3-5 real external links.
4. If a quiz is warranted, add 3-5 questions following the existing pattern.
5. Add an entry to `artifacts.json` (title, description, topic, date, slug).
6. Run `python build.py` to regenerate `index.html`.
7. `git add`, commit, and push — GitHub Pages redeploys automatically.

## Privacy

Every page ships `noindex, nofollow, noarchive, nosnippet` meta tags. The
site is not encrypted or access-controlled — anyone with the direct link can
view it — so nothing sensitive gets published here.
